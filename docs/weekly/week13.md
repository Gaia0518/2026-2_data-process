# 13주차 (11/26) 2차: 배치 기반 배열

## 1. 도곽 모서리 지정 (완료)
- 도면마다 빨간 도곽선의 네 모서리를 클릭 → 자르기·기울기·배율 자동 계산, 도곽 바깥 여백은 숨김
- **빨간 선에 맞추기**: 모서리 근처에는 빨간 좌표 숫자(+200, 0 등)가 있어서, 모서리에서 안쪽으로 뻗은 도곽선 구간의 붉은 정도를 합산해 선 위치를 찾음. 선이 흐리면(강도 8 미만) 클릭한 자리를 그대로 쓰고 주황색으로 표시
- **기준 도곽**: 처음 지정한 도곽 크기가 기준. 다른 도면은 배율이 자동으로 맞춰짐 (스캔 해상도 차이 보정)
- 다음 모서리 자동 확대, 적용 후 다음 도면으로 이어서 지정
- 자동 배열은 도곽을 지정하면 기준 도곽 크기를 칸으로 사용
- `project.json`에 `frameSize`, `sheets[].frame` 추가 → `tools/export.py`도 도곽 바깥을 잘라 출력

### 실제 원도 시험 (남산정 7·8·11·2호)
| | 정밀 검출값과의 차이 |
|---|---|
| 모서리를 5~6px 빗나가게 클릭 → 맞추기 후 | 대부분 0~4px, 최대 6px |
| 7호 배율 | 자동 96.5% (도곽 1560×1245 → 기준 1505×1201) |
| 기울기 | 4장 모두 ±0.1° 이내로 보정 |

- 7호 아래쪽 도곽선은 빨간색이 거의 지워져 있음 → 주황 표시로 사람이 확인하도록 함

## 2. 第○號 이웃 번호로 자동 배열 (다음)
- 도면마다 도면 번호와 위·아래·왼쪽·오른쪽 이웃 번호(가장자리의 「第○號」)를 입력
- 하나의 도면에서 시작해 이웃을 따라가며 격자 위치(행·열)를 계산 → 도곽 크기 칸에 자동 배치
- 이웃 번호가 서로 맞지 않으면(예: 8호 아래가 9호인데 9호 위가 8호가 아님) 표시
- 배치도(0번)를 옆에 띄워 놓고 칸을 눌러 번호를 넣는 방식도 함께 검토

## 3. 곱하기가 까맣게 나오는 문제 (사용자 테스트, 대구 시가지 흑백 원도)
- 원인: 곱하기는 겹친 곳의 어두움이 누적됨. 흑백 스캔은 종이 모눈·얼룩이 모두 검은 점이라 2~3장 겹치면 거의 검게 됨 (바랜 컬러 원도도 갈색으로 짙어짐)
- 해결: 겹치기 **어둡게**(darken)를 기본값으로. 겹친 곳에서 더 어두운 값만 남기므로 선은 모두 보이고 누적되지 않음
- **종이 밝게**: 종이 밝기(가운데 영역 상위 15% 밝기)를 흰색으로 끌어올림 (편집기·export.py 동일)

## 4. 배치도 인식 → 확인·수정 → 자동 배열 (방식 변경)
사용자 요청: 0번 배치도에서 1번부터 끝까지 배치를 자동으로 인식하고, 사용자가 고친 배치대로 자동 배열

**흐름**
1. 원도를 처음 불러오면 배치도 인식 창이 자동으로 열림
2. 전체 도엽 수(표지의 「○○枚」)를 넣고, 0번에서 배치도 부분을 드래그
3. 자동 인식: 칸 크기·위치 → 번호가 적힌 칸 → 번호 매기기(기본: 오른쪽 열부터 위→아래)
4. 확인·수정: 빈 칸 클릭(빠진 번호 넣기), 번호 칸 선택 후 번호 고치기(겹치면 자동 맞바꿈)·빼기, 1번부터 순서대로 클릭, 칸 하나 그려서 격자 맞추기, 격자 밀기·줄 늘리기
5. 적용 후 자동 배열: 배치표의 모든 칸이 사각 틀(○호)로 깔리고, 원도는 도면 번호(없으면 파일 순서)로 제 칸에 놓임. 배치표에 없는 원도는 아래쪽에 따로

**자동 인식 방법**
- 칸 테두리는 길게 이어지고 번호 획은 짧음 → 선의 연속성으로 칸 간격 탐색
- 칸 수가 전체 도엽 수의 0.9~4.5배인 크기만 후보로 (종이 모눈·2배 크기 오인 방지), 칸 비율은 도곽 비율
- 번호는 칸 한가운데 있음 → 격자가 반 칸 밀린 경우를 바로잡음
- 칸 가운데 잉크가 많은 순으로 전체 도엽 수만큼 고름
- 한자 번호를 글자로 읽지는 않음 (브라우저에서 불가) → 순서 규칙으로 번호를 제안하고 사람이 고침

**시험 결과**
| 표지 | 칸 크기·위치 | 번호 |
|---|---|---|
| 남산정 (컬러, 2000px, 31매) | 빨간 칸 선과 정확히 일치 (80×64px) | 7·8·9호 세로, 7호 왼쪽 15호, 8호 왼쪽 16호, 9호 오른쪽 2호가 가장자리 번호와 일치. 빨간색으로 고쳐 쓴 11호 칸 1곳은 수정 필요 → 한 번 고치니 4장 모두 제자리 |
| 대구 시가지 (흑백, 1125px, 68매) | 42×33px로 제안 (칸이 작고 배치도 안에 필지가 빽빽함) | 정답을 몰라 검증 못 함. 영역 오른쪽 끝 글씨 열이 칸으로 잡히는 등 수정 필요 |

- 원도 가장자리의 이웃 번호(대구: 1호 아래 2호 아래 3호 아래 4호, 1호 왼쪽 5호)로 보면 "오른쪽 열부터 위→아래" 순서 규칙이 맞음

## 5. 대구 시가지 정답 배치로 검증 (사용자 제공 PDF, 11/13)
사용자가 고해상도 0번(4032×3200) 위에 68칸과 번호를 표시한 PDF를 제공 → 칸·번호를 추출해 자동 인식과 비교

**정답에서 확인한 것**
- 번호 순서는 **오른쪽 열부터 위→아래** (기본 순서 규칙과 같음)
- 칸 테두리가 따로 그려져 있지 않고 **종이 모눈선(약 30px)의 5칸·4칸마다**와 겹침 → 선만으로는 어느 모눈선이 칸 경계인지 알 수 없음
- 번호(一一, 二三 등)는 칸 한가운데에 세로로 적혀 있음

**고친 것**
| | 전 | 후 |
|---|---|---|
| 격자 위치 | 반 칸 밀림 (번호가 칸 경계에 걸침) | 번호가 칸 가운데 오는 위치를 모든 후보에서 고름 → **정답 68칸이 모두 서로 다른 칸에 정확히 대응** |
| 칸 크기 | 800px로 줄여 계산 | 1200px, 0.1px 단위로 다시 맞춤 |
| 번호 칸 고르기 | 진한 순 (48/68) | 한 덩어리로 이어 붙이기 (편집기에서 49/68, 파이썬 시험 53/68) |
| 수정 | 칸 하나씩, 번호도 직접 고침 | 칸을 넣고 빼면 번호 자동으로 다시 매김, **끌어서 여러 칸 한 번에** 넣기·빼기 |

**수정에 드는 수고 (대구 68칸)**
- 1번부터 하나씩 클릭: 68번
- 자동 제안 + 칸 하나씩 고치기: 57번
- 자동 제안 + **끌어서 고치기: 17번** → 68칸 번호 모두 정답과 일치

**남은 한계**
- 배치도 옆 세로 글씨(「異動地測量完成」 등)나 시가지 필지 선이 빽빽한 칸을 번호 칸으로 잘못 고름 (약 30%)
- 행정구역 변경으로 번호를 빨간색으로 고쳐 쓴 칸(남산정 11호 등)은 순서 규칙으로 알 수 없음 → 직접 고쳐야 함

## 6. 도곽 자동 지정 (사용자 요청: 모서리를 일일이 찍지 않게)
**방법** (`app/js/autoframe.js`)
1. 원도마다 도곽 후보 사각형: 길게 이어진 가로·세로 선 4개, 비율 약 1.25, 종이 가장자리 7% 안쪽, 선이 모서리에서 끝날수록 높은 점수 (모눈선·종이 테두리는 끝까지 이어짐)
2. **투표**: 가장 많은 원도에 공통으로 나타나는 도곽 크기(이미지 대비 비율)를 고름 — 점수만으로 고르면 종이 테두리를 잡는 경우가 있었음
3. 그 크기로 사각형을 1px씩 옮겨 네 변이 가장 잘 겹치는 위치 탐색. 흐리거나 지워진 변은 가로 길이와 비율로 추정
4. 컬러 원도는 모서리를 빨간 선에 맞춰 기울기까지 계산
5. **확인 필요** 표시: 점수가 다른 원도의 60% 미만이거나, 도곽 크기가 다른 원도와 2.5% 넘게 다를 때

**시험**
| | 결과 |
|---|---|
| 남산정 컬러 4장 | 4장 모두 정밀 검출값과 4px 이내. 아래 변이 지워진 7호는 '확인 필요'로 표시 (실제로는 맞음) |
| 대구 흑백 4장 (1125px 축소본) | 3장 맞음. 1호는 틀렸고 '확인 필요(크기 6% 다름)'로 걸러짐 |
| 시간 | 4장 약 2~3초 |

- 원도를 불러오면 도곽 자동 지정 → 배치도 인식 창 순서로 자동 진행
- '도곽 수정' 버튼은 확인이 필요한 원도부터 차례로 열어 줌

## 7. 도곽 펴기 (수직·수평 맞춤)
- 사용자 요청: 모서리를 지정하면 수직·수평을 맞춰 줄 것
- 기존: 네 변의 평균 기울기만큼 회전 → 사다리꼴로 틀어진 스캔은 변마다 기울기가 남음
- 변경: 네 모서리를 직사각형으로 펴는 원근 보정(투영 변환)을 기본으로. 도곽 지정 창에서 네 점을 찍으면 **펴진 모습**을 바로 보여 주고(확인용 격자), [수직·수평 펴기]를 끄면 예전 방식(회전만)
- 출력: 브라우저는 원본을 그 자리에서 펴서 합성, `export.py`는 PIL PERSPECTIVE 변환 → 두 출력의 픽셀 차이 평균 3.8/255
- 시험: 남산정 7호(모서리가 위 4px·아래 11px 틀어짐)를 편 뒤 네 변의 양 끝 차이 0~2px (0.1° 미만)

## 8. 배치도 번호: 열 따라 긋기 (개선안 A)
- 자동 인식은 **칸 격자만** 맡고(정확함), 번호는 사람이 번호 순서대로 열마다 첫 칸 → 끝 칸으로 그어서 매김
- 자동 인식 직후 바로 긋기 모드로 열림. 자동 제안은 주황 점선으로 안내만 하고, 맞으면 [자동 제안 그대로 쓰기]
- 빠르게 그어 건너뛴 칸도 채움, 이미 매긴 칸은 건너뜀, 번호 순서 선 표시, Backspace로 마지막 긋기 취소
- 시험 (대구 68칸 정답): **긋기 10번 → 68/68 일치** (기존: 자동 제안 49/68, 끌어서 고치기 17번)

## 9. 원도 대응표
- 원도와 배치도 칸은 도엽 번호로 짝지음: 도면 번호를 적었으면 그 번호(한자·숫자), 없으면 파일 순서, '—'이면 배치에서 뺌
- [원도 대응표]: 도엽 번호마다 배치 칸(행·열), 원도 썸네일, 원도 선택, 상태(연결됨 / 원도 없음 / 배치도에 칸 없음 / 중복)
- 번호에 원도를 고르면 그 번호를 쓰던 다른 원도는 자동으로 빠짐, [모두 파일 순서로], [닫고 자동 배열], 되돌리기 한 번에 전체 취소
- 왼쪽 목록에 원도마다 '○호' 표시 (칸이 없으면 '칸 없음', 빠진 원도는 '대응 없음')
- 배치 적용 후 칸과 짝지어지지 않은 원도가 있으면 상태 표시줄로 안내
- 시험: 남산정 원도 4장(파일 순서 1~4)을 표에서 2·7·8·11호로 바꾸고 자동 배열 → 4장 모두 해당 칸으로 이동, Ctrl+Z로 원상 복구
